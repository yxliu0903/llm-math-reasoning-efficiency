检索截止：2026-10-10 UTC。近两年窗口：2024-10-10—2026-10-10；“近半年”窗口：2026-04-10—2026-10-10。本文把“冗长”定义为显式 CoT token/step 过多、答案收敛后的无效继续推理、统一预算导致的过度/不足思考、KV/上下文累积，或为降低上述成本而采用的显式压缩/潜在推理/自适应停止方法。

先给结论

研究已经从“给长度加惩罚”转向“识别何时、哪一步、哪一种 token 是冗余”。现有方法可以归为五个层次：

  1. 问题级预算路由：根据难度、置信度或未来收益在 NoThink/Short/Long 或不同 rollout 数之间分配预算。
  2. 轨迹级早停：检测答案稳定、语义重复、回溯爆发或注意力状态，在收益低于 token 成本时停止。
  3. 内容级/训练期压缩：从正确轨迹中删除重复段、蒸馏短轨迹，或用分段 credit assignment 把“得到答案”和“答案后的废话”分开。
  4. 表示级压缩：把可压缩 span 变为 latent/abstract/function token，或者用几何连续状态代替离散文字。
  5. 系统级降本：KV cache 合并/预算分配、量化后 overthinking 修正、共享预算和成本评测。

统一目标可写成 \[ \max_\pi \; \mathbb E[A(y|x)]-\lambda\,\mathbb E[L(y|x)],\qquad \text{s.t. }\mathbb E[L]\le B, \] 其中 \(A\) 是答案正确率，\(L\) 是思考 token、步骤、FLOPs 或 latency。真正困难在于 \(A(L)\) 通常是倒 U 型：短了欠思考，长了过思考；而且 \(L^*(x)\) 随问题难度和模型能力变化。若只用 \(r=A-\lambda L\)，策略很容易学会“少说但漏掉关键步骤”。

分类后的关键判断

  • 最直接改善数学 CoT 冗长的主线是 B+C：B 在推理时截断，C 在训练时改变策略；二者可以串联，但不能把同一段节省重复计算。
  • 最可能形成下一代模型架构的主线是 D：latent/abstract 表示把成本从“输出多少字”转为“隐藏状态做多少次更新”，但可审计性和错误定位明显变差。
  • 最容易被误判为已经解决冗长的主线是 E：KV 压缩和低比特量化减少内存/单 token 成本，却可能诱发更长的 CoT；必须同时报告生成长度和端到端 latency。
  • 最适合建立统一实验协议的主线是 F：这些工作说明平均 token、最终准确率和单题预算都不足以描述实际部署的效率。
  • 推荐的组合基线：先用 A 分配题级预算，再用 B 做在线停止，训练阶段用 C 的正确性优先 credit，系统层用 E 记录 KV/量化副作用；D 作为需要重新验证忠实性的独立架构路线。

1. STACK — Think Less, Know More（2604.09150，2026-04-10）

背景。 数学 CoT 让模型逐步生成解题过程，每一步都可能继续展开、压缩或停止。不同题目的冗余来源不同，单一规则难以同时处理知识不足、重复解释和无效验证。

代码状态：未发现公开代码/项目页。

方法。 STACK 对每个 reasoning state 做 step-wise 压缩：在线构造 long/short 对比样本；状态不确定或有 reasoning bias 时调用检索知识指导压缩，状态已经正确但过长时用 self-prompted compression；再以答案收敛作为早停信号。训练将 PPO 与 DPO 的 reward difference 结合，让策略学习“按状态选压缩器”。可抽象为 \(a_t\in\{\text{retrieve-compress},\text{self-compress},\text{continue}\}\)，最大化 \(R=A-\lambda L\)。

动机/目标。 统一压缩把关键自纠错步骤和重复核验一视同仁；STACK 假设冗余来源随推理阶段变化。作者在三个数学基准报告平均长度降 59.9%、准确率升 4.8 个百分点。

缺陷/新问题。 在线对比采样和检索带来训练开销；检索错误会把偏置写入压缩轨迹，频繁检索还会增大上下文、稀释注意力。它依赖可验证答案和文本知识，开放题、工具/多模态场景的“状态标签”并不可靠；PPO+DPO 的两个信号可能互相争夺梯度。新问题是：压缩器学到的是通用冗余还是某个 benchmark 的检索模板？

2. When More Thinking Hurts（2604.10739，2026-04-12）

背景。 测试时计算指通过额外采样、思考或验证换取准确率。思考越久不一定越好，模型可能在得到正确答案后继续怀疑并改错，因此需要区分有益思考与有害过度思考。

代码状态：官方项目/补充材料，未发现独立仓库。

方法。 这是诊断和成本评测框架而非训练器：测 \(\Delta A/\Delta L\) 随预算的边际收益，记录“先得到正确答案、随后又放弃”的 harmful overthinking，并按难度估计每题最优思考长度。停止中等预算即可维持准确率。

动机/目标。 反驳“更多 token 单调更好”的默认假设，为动态停止提供曲线证据。

缺陷/新问题。 诊断依赖可强制截断和可解析答案；边际收益会随解码温度、模型版本、答案抽取器改变。它告诉我们哪里该停，却没有可部署的 stopping policy；如果直接把观察到的最优长度硬编码，会在分布外题目上欠思考。

3. AdaCompute · Code（2604.14853，2026-04-16）

背景。 推理预算可以是每题的 rollout 次数或生成 token 数，统一分配会浪费简单题的计算并挤压难题预算。自适应方法需要比较各题不同动作的成本和成功概率，再满足总预算约束。

代码状态：官方代码。

方法。 将问题级分配写为约束优化：\(\max \sum_i A_i(a_i)\) s.t. \(\frac{1}{n}\sum_i C_i(a_i)\le B\)。Lagrangian \(A_i(a)-\eta C_i(a)\) 使每题有 oracle action，利用成本关于 \(\eta\) 的单调性二分精确命中预算；再用轻量分类器从便宜特征预测 oracle action（SOLVE-THEN-LEARN）。

动机/目标。 uniform rollout 把预算浪费在简单题、不给难题足够计算。MATH/GSM8K 报告相同预算下最高约 12.8% 相对准确率提升，模仿准确率超过 91%。

缺陷/新问题。 oracle 需要先为每题跑多种动作，离线成本高；分类器误差在 action gap 大的题上会放大 regret。平均预算约束可能牺牲尾部难题或高价值题，且训练分布固定，不能处理题目价值不同的在线队列。

4. TRACE · Code（2604.17304，2026-04-19）

背景。 早停常依据并行回答的投票分布或模型置信度判断答案是否稳定，但多步推理中的单点置信度会波动。观察一段时间的持续一致性，才能减少把短暂高置信误判为收敛。

代码状态：官方代码。

方法。 训练-free 地聚合最近多个步骤的答案一致性与置信度轨迹：不是看单点 \(p_t\)，而是看窗口内的持久性/趋势，满足双信号阈值才停止。报告 token 降 25–30%，准确率损失 1–2%。

动机/目标。 单步 confidence 在多步自纠错中会抖动；时间聚合更接近“已经收敛”。

缺陷/新问题。 一致的错误答案会触发过早停止，难题的正确答案可能在短暂低置信后出现；窗口大小和阈值对模型/温度敏感。它只观察答案分布，无法判断证明结构是否完整，可能留下“答案对但过程断裂”的前缀。

5. CRISP · Code（2604.17297，2026-04-19）

背景。 Transformer attention 描述 token 与上下文的关联，推理模型还常用结束标记表示思考段落完成。若结束标记持续关注某些位置，attention 就可作为判断步骤重要性的线索。

代码状态：官方代码。

方法。 发现 </think> 的 attention pattern 是信息锚点，用其对原子操作进行 saliency pruning，构造模型自身的压缩目标，再蒸馏成短 CoT。核心假设是终止 token 的反向注意力能分出必要步骤与冗余。

动机/目标。 外部 compressor 不懂源模型内部动力学，会误删自纠错；CRISP 报告 50–60% token reduction 且准确率基本不变。

缺陷/新问题。 attention 是相关性而非因果重要性；换 tokenizer、没有显式 </think> 的模型或开放题时锚点失效。数据构造仍需迭代搜索，离线成本把推理节省转移到训练；主要在结构化数学上验证，可能培养“看起来连贯但缺少隐含条件”的短链。

6. TRACES · Code（2604.21057，2026-04-22）

背景。 数学轨迹包含假设、计算、验证和重复核验等不同功能。只看长度或单次置信度无法判断当前片段是否仍在推进解题，因此需要识别行为类型及其转移。

代码状态：疑似代码仓库，官方关联未确认。

方法。 实时给推理段落打行为标签（探索、验证、重复核验等），从标签转移模式学习可解释 early-stop 规则。核心观察是模型得到正确答案后会从有生产性的行为转向过度验证；MATH500/GSM8K/AIME/MMLU/GPQA 报告 20–50% token reduction。

动机/目标。 只看长度或最终 confidence 无法知道某一步的功能；step type 提供可解释信号。

缺陷/新问题。 在线标签器本身消耗计算且可能误读新颖的自纠错；困难题需要保守阈值，收益不稳定。标签是表面语言行为，模型可学会规避“重复”词而保留语义冗余，产生 reward hacking。

7. Abstract CoT · Code（2604.22709，2026-04-24）

背景。 自然语言 CoT 同时承载计算和解释，通常很长；latent reasoning 用隐藏向量或离散代码保存中间状态，可减少逐词生成。abstract token 试图在短序列、可训练性和可解释性之间折中。

代码状态：疑似代码仓库，官方关联未确认。

方法。 用保留词表中的离散 abstract tokens 代替自然语言 CoT。先把 verbal CoT mask 成 bottleneck 做 SFT，再自蒸馏 prompt→abstract code，最后在 codebook 约束下 RL。短 token 序列承载推理状态，报告最多 11.6× 更少 reasoning tokens。

动机/目标。 连续 latent 方法效果落后于 verbal CoT；离散 code 兼顾可训练性和短序列。

缺陷/新问题。 abstract token 不可读、难监控，错误定位和过程监督更难；codebook 与 backbone/tokenizer 强耦合。短序列减少解码步却可能增加每步状态复杂度，且训练阶段仍需长 CoT。它把“冗长文本”换成“不可解释内部状态”，会削弱数学证明的可审计性。

8. Large Language Models Decide Early and Explain Later（2604.22266，2026-04-24）

背景。 模型可能在完整解释结束前就基本确定答案，后续 token 只是把决定翻译成理由。这使“决定答案”和“结束解释”成为两个阶段，但答案稳定不等于证明完整。

代码状态：未发现公开代码/项目页。

方法。 对每个 partial prefix 强制 answer completion，追踪答案何时最后一次改变；探针式停止在答案稳定后终止。Qwen3-4B 中只有约 32% query 会改变最终预测，最后一次切换后平均还生成 760 token；简单启发式可省约 500 token、准确率下降约 2%。

动机/目标。 区分“决定答案”和“事后解释”；后者是低收益延迟。

缺陷/新问题。 中间答案可能只是猜测，强制补全本身会改变 hidden state；答案稳定不等于证明稳定。对多答案、程序执行和需要最后一步计算的题，探针会把未完成的推理当作 post-decision explanation。

9. ICR（2605.07316，2026-05-08）

背景。 强化学习会为同题采样多条轨迹，并记录正确性和长度。长度—正确率关系能提示过度或不足思考；固定长度惩罚可能造成欠思考，所以需要短且正确的当前策略样本作参照。

代码状态：官方项目/补充材料，未发现独立仓库。

方法。 观察 rollout group 中 length–accuracy correlation：负相关代表 overthinking，正相关代表 underthinking。取组内最短正确样本形成“虚拟短分布”，在 on-policy 目标中正则策略靠近它，而不是直接加 length penalty 或硬截断。

动机/目标。 静态长度惩罚会把模型从过思考推到欠思考；短而正确的样本已自然存在于 rollout 中。

缺陷/新问题。 需要组内出现正确短样本；早期/难题可能没有，信号稀疏。ICR 是软约束，不能给严格 latency SLA；相关性定义会被题目混合、temperature 和 group size 扭曲。未来需解释模型容量、难度和 rollout 多样性如何共同决定 Pareto 前沿。

10. ExpThink（2605.07501，2026-05-08）

背景。 模型能力会随训练变化，同一道题早期可能需要长思考、后期只需几步。固定长度目标无法跟随这种变化，历史最短正确解可以提供动态的简洁性参照。

代码状态：官方项目/补充材料，未发现独立仓库。

方法。 经验缓冲区记录每题迄今最短正确解；三档 reward：短且正确满分、长但正确折扣、错误零分。阈值随能力提升自动收紧；用 correct-count 而非标准差归一化 advantage，让难题保留准确率梯度、简单题强化简洁。

动机/目标。 固定长度权重假设能力不变，无法反映同一题在训练后变容易；报告最多 77% 长度下降且准确率提升。

缺陷/新问题。 依赖可靠答案 verifier 和数学数据；短样本的偶然捷径会被记忆并放大。阈值/折扣仍是经验超参，experience buffer 可能偏向早期发现的模板，阻碍探索。

11. MPD（2605.08776，2026-05-09）

背景。 知识蒸馏把教师行为迁移给较小学生，教师重写的短解有助于压缩 CoT。但学生在线采样与教师示范有分布偏移，需要同时处理探索、重写和概率对齐。

代码状态：官方项目/补充材料，未发现独立仓库。

方法。 学生先采样 verbose trajectory，教师在同一题上重写为 concise trace，再对压缩轨迹做 KL 对齐；兼顾 on-policy 探索和 teacher compression，避免纯 off-policy 分布偏移。Qwen3-1.7B 最多省 27.1% token。

动机/目标。 大模型教师通常比小模型更会直接作答；把“短行为”迁移给部署友好的小模型。

缺陷/新问题。 论文明确不显式优化 correctness，错误 student trace 可能被教师压缩后学习；教师改写风格成为单点偏差。教师推理/重写成本可能超过学生节省，且 teacher/student tokenizer、能力差距会造成语义错配。

12. LEAD · Code（2605.09806，2026-05-10）

缺陷/新问题。 需要同时运行 full-precision teacher，部署节省被 teacher 比较抵消；token discrepancy 不一定表示冗余，可能是量化模型真正需要的纠错。对没有 FP reference 的边缘部署不可用。

49. CASK: Core-Aware Selective KV Compression for Reasoning Traces（2604.10900，2026-04-13，邻接）

背景。 自回归模型把每个历史 token 的 key/value 存入 KV cache，以免每一步重新计算；长推理会让该缓存持续膨胀。缓存中的 token 作用并不相同：有些承载答案约束或关键中间量，有些只是可合并的草稿，因此压缩前需要区分必须保护的 core 与可整理的 scratch。

代码状态：仅发现外部基线仓库，非本文代码。

方法。 把 reasoning KV 分成 protected core 与 mergeable scratch，核心保持、scratch 选择性 consolidation；prompt-heavy 时先 prefix eviction、再 decode consolidation。

动机/目标。 仅改 scorer 不会改变 keep-set；行为保持的结构合并比排名淘汰更适合长推理。

缺陷/新问题。 core/scratch 的边界依赖任务和答案形成阶段；合并 scratch 可能破坏跨步引用。主要报告 KV continuation fidelity，不等于完整数学准确率和端到端成本。

50. ReasonAlloc/CASK 类系统工作的共同边界

背景。 系统层面，删掉缓存 token 可能减少显存，却也可能让模型失去上下文并生成更长的补偿轨迹；相反，保留上下文可能减少重算但增加 KV 操作。真实成本应同时计入 prefill、decode 和缓存读写，而不能用最终 CoT 长度或缓存保留率单独代表。

代码状态：综合边界项，无单篇论文或独立代码仓库。

二者都说明“缓存 token 数”与“推理 token 数”是耦合的：保留更多上下文可能减少重算，删得太多会诱发更长轨迹。部署时应报告 \(\text{latency}=T_{prefill}+T_{decode}+T_{KV\ ops}\)，不能只报告 CoT 长度。它们是数学推理效率的系统层补充，而非替代语义压缩。

  • 2024 年末：先发现问题。 C3oT、CCoT、TALE/Token-Budget-Aware 和 “Do NOT Think That Much” 建立“CoT 太长、预算应按题目变化”的问题定义；MCoT 通过 Markov 摘要减少 KV 依赖。
  • 2025 年上半年：压缩与早停并行。 TokenSkip、ConCISE、Long–Short SFT、ReCUT、AALC、Dynamic Early Exit 等开始用 compressor、confidence、step trail 或 preference optimization；“When More is Less” 给出倒 U 曲线和 simplicity bias，成为后续方法的理论动机。
  • 2025 年下半年：从长度转向内容/自适应。 overthinking/self-doubt、内部/外部 redundancy、SSPO、BudgetThinker、SEER、ARS、entropy regulation 等分别处理反思、预算控制和 token/step 重要性；HERMES 把形式验证插入数学链，兼顾准确率和成本。

我认为最重要的未解决问题

  1. “答案正确”不等于“推理充分”。 早停监督大多依赖最终答案 verifier，容易训练出早答、后解释或不可审计 latent state。
  2. 长度不是冗余的充分统计量。 重复 token、必要自纠错、低概率关键跳转在表面长度上不可分；entropy/logprob/attention 单信号都被近期反例削弱。
  3. 平均预算掩盖尾部风险。 共享预算和难题分配需要 risk-sensitive objective，例如最大化 \(\sum_i v_i A_i\) 同时控制 P99 latency，而非只约束平均 token。
  4. 训练节省与推理节省不同。 许多 compression 方法离线需要多 rollout、教师重写、检索或树搜索；应同时报告 data-construction FLOPs、训练 FLOPs、prefill/decode latency 和 KV memory。
  5. 数学 benchmark 的可验证性造成选择偏差。 结论常在 GSM8K/MATH/AIME 成立；开放数学证明、形式 Lean、工具调用和多语言题仍需验证。
  6. 监控与忠实性冲突。 latent/abstract/function token 能降成本，却让人类和 verifier 难以检查；短 CoT 可能只是把错误藏到不可见状态。
